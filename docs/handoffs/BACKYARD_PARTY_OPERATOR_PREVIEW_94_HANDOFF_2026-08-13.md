## Primary outcome

Fixture-profile correction is now a general Local-profile workflow instead of
a permanent White/Amber exception. The same fixture-function truth also has a
bounded component snapshot/controller model and a deterministic planner into
existing fixture/group Ember Action commands. Neither foundation is yet a
production skin-runtime surface or a persisted/activated Action asset.

## What changed

- Studio → Fixture Profiles opens **Channel Map Workbench** with all 53 shared
  semantic parameters, readable channel rows, category/safety descriptions,
  and direct access to the existing named-range editor.
- **Add at next open channel** fills the first unused footprint slot and only
  grows the footprint when the existing footprint is occupied. **Fill unused
  gaps safely** adds explicit zero constants while respecting fine channels.
- **Review + Exchange Functions** supports any two compatible ordinary direct
  8-bit mappings in a Local profile. It keeps physical offsets, ranges,
  defaults, blackout/highlight values, and owners fixed while exchanging the
  semantic properties. Stale, unsafe, compound, fine-channel, incompatible,
  and invalid candidates fail without partial mutation.
- Built-in and imported profiles stay immutable. Use **Duplicate to Edit**,
  make the Local draft change, then **Save Profile** so validation/compilation
  and any accepted Patch rebind remain authoritative.
- A running Live package is an immutable compiled snapshot. After saving a
  profile correction, stop and start the show before expecting Live output to
  use it.
- `ember.fixtureFunctionBrowser` provides bounded stable-ID rows, search,
  category filters, coverage/safety evidence, accessibility text, and exact
  existing set/release invocation construction. It does not dispatch or own
  live state.
- `ember.fixtureProfileEditor` and `ember.fixtureFunctionBrowser` are bridged
  registry component contracts. They are not proof of skin-runtime activation,
  Designer placement, toolkit rendering, or component persistence.
- The fixture-control Action planner re-resolves a catalog choice and produces
  deterministic canonical source plus prepared/foundation/executable IR for
  one fixture or an eligible exact group. Mixed, partial, divergent, stale,
  protected, and unconfirmed safety-gated inputs fail closed; no partial group
  sequence is emitted.
- The generated Ember Action registry adapter materializes enum values from
  canonical `schemaRef` contracts. The planner does not persist, activate,
  schedule, or bind an Action.

## White/Amber test route

1. Confirm the fixture's exact display mode, start address, interface route,
   and profile revision before enabling output.
2. For a built-in/imported profile, choose **Duplicate to Edit** and patch/save
   the Local replacement when prompted.
3. Open **Channel Map Workbench**. Select the two observed direct channels and
   review the complete exchange summary; do not exchange chart-dependent,
   compound, or safety functions.
4. Save the profile, accept the intended Patch rebind, stop/start Live if it
   was active, and test White then Amber separately at low intensity.
5. Record the observed channel/mode/address result for each physical IR-4.
   Software tests do not establish that either owned fixture is qualified.

The compiled IR-4 6CH regression proves both semantic writes follow the Local
profile after CH4/CH5 are exchanged: White reaches the profile's White offset
and Amber reaches its Amber offset. It does not prove the physical light,
display mode, address, interface, cable, or raw response.
