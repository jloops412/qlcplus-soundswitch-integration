# V34 pinned native engine contracts

This suite compiles the **unchanged** QLC+ engine and QML `VCButton`/`VCWidget`
implementations at `a124abebe0b5ad6077727c561a5a0e1f3730810c`, with Qt **6.8.1**.
It loads the candidate workspace using native `Doc::loadXML` and
`VCButton::loadXML`, runs native master/universe threads, and captures native
output frames. Candidate MIDI translation and effect composition are compiled
from this repository.

Unlike the portable translator tests, feedback is generated by native button
state, passed through `VCWidget::sendFeedback`, `InputOutputMap::sendFeedBack`
and a Universe feedback patch into the candidate translator. The test does not
inject fabricated feedback values.

The explicit test boundaries are:

- WinMM calls use the existing deterministic MIDI device adapter.
- Undo/network history is a no-op `Tardis` adapter. This does not own playback,
  input, feedback, Scene, fader, or output state.
- An output plug-in captures bytes instead of contacting hardware.
- A focused active-page input dispatcher delivers translated channels to the
  native button pressure slots. The full page/frame hierarchy and QML visuals
  are not instantiated, so page navigation and rendered GUI layout are outside
  this suite.
- The focused composition assertion feeds actual native U1/U4/U5/U6 frames
  through the candidate `SoundSwitchEffects`; USB scheduling and hardware
  transport are outside this suite.

The first scenario is an intentional negative control. It confirms that native
`MasterTimer::stopAllFunctions()` alone leaves a flashed Scene active on this
pin. The V34 STOP scenario must then clear Flash state through the real native
mouse-command feedback and the candidate translator before stopping ordinary
Functions. The visible command starts an empty native Scene; an enabled native
observer emits positive feedback only when the master timer actually starts
that Scene. This also closes the pending-start queue race without a timer delay
or core patch. This catches interactions missed by isolated translator tests.

Additional scenarios check separate WHITE/BLACK/UV hold and latch Scene
ownership, real HTP ownership markers, independent color latch/hold marker
release, BLACK priority over later nonzero WHITE output, actual Chaser
start/stop feedback, and immediate manual-owner start followed by mouse or
Shift+Play STOP. A second negative control proves that disabling a native
observer suppresses its feedback. Saved Frame Disabled XML is not interpreted
as runtime state because the pinned Frame loader ignores that saved element.

## Run

Install Qt 6.8.1 with Multimedia and the usual CMake/Ninja, ALSA, udev and
OpenGL development dependencies. Then:

```sh
git clone https://github.com/mcallegari/qlcplus.git ../qlcplus-pinned
git -C ../qlcplus-pinned checkout --detach a124abebe0b5ad6077727c561a5a0e1f3730810c
cmake -S qlcplus/tests/v34-native -B build-v34-native -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH=/path/to/Qt/6.8.1/gcc_64 \
  -DQLCPLUS_SOURCE_DIR="$(cd ../qlcplus-pinned && pwd)"
cmake --build build-v34-native --parallel 4
ctest --test-dir build-v34-native --output-on-failure
```

For a captured run with workspace, production-source, fixture, test-source,
executable and engine hashes:

```sh
python qlcplus/tests/v34-native/run_and_record.py \
  --build-dir build-v34-native --evidence-dir /path/to/evidence
```

`V34_WORKSPACE` and `V34_FIXTURES` can select an exact packaged workspace and
fixture folder. Defaults are the V34 generated workspace and the protected V32
testing package's unchanged fixture definitions. CMake rejects a different QLC+
commit, tracked engine/VC source modifications, or a different Qt version.

Passing is **software evidence on the Linux pinned engine and Qt version**.
It is not Windows host ABI/load evidence, physical Control One/Micro behavior,
full GUI acceptance, every Autoloop's visual quality, or gig qualification.
