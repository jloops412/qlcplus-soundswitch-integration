## `.ssfile` timeline evidence

The 96 `SSAutoLoop*.ssfile` files share a recognized SoundSwitch binary header and contain repeated target blocks keyed by Venue entity IDs.

Observed target-block structure contains two distinct authored data families:

1. **A records — normalized intensity timeline**
   - repeated 17-byte records;
   - timestamp fields are source-reference milliseconds (600 ms per beat in this corpus; 19,200 ms for 8 bars and 38,400 ms for 16 bars);
   - value field is unsigned 32-bit normalized fixed-point: `valueRaw / 0xffffffff`;
   - duplicate timestamps encode hard transitions in the observed corpus;
   - interpolation between distinct points is strongly consistent with authored smooth pulse/fade behavior, but should remain `DeterministicallyTranslated` until one-change delta evidence proves the interpolation rule.

2. **B records — timed color segments**
   - repeated 36-byte records;
   - start/end time plus two packed color words at each endpoint;
   - the first packed word carries RGB bytes. Its high byte is **not safe to interpret as opacity**: real authored segments include `0x00RRGGBB` values with nonzero RGB, so migration must preserve/use RGB independently of that byte until controlled-delta evidence identifies its semantics;
   - the second packed word carries direct-emitter data consistent with the Static Look format: upper bytes map to Amber / White / UV respectively in the observed corpus;
   - examples include warm tube segments with nonzero direct White and source loops whose RGB values match their named color families;
   - interpolation of RGBWAUV endpoints inside a timed segment is strongly supported by the data shape but remains `DeterministicallyTranslated` until one-change delta evidence proves the exact interpolation rule.

## Current V1 representation limit

Preview 101 format-1 Autoloops are whole-Static-Look sequences with at most 32 steps, while a project supports 256 Static Looks and 32,768 assignments.

A single format-1 project cannot preserve all 96 rich source timelines at useful sampling fidelity because each sampled source state must become a helper Static Look. This is a representation/capacity limitation, not permission to collapse real timelines into name-derived presets.

For V1 physical comparison, prefer source-faithful bank/chunk reconstruction projects with a migration report. The V2 semantic source/program model under #57/#60 is the proper long-term importer target for all 96 loops in one project.

## Translation rules for current rig test

Current physically relevant destination:

- source uplights 198–201 -> IR-4 #1–4, 10CH semantic profile;
- source Tube 1–4 cell IDs -> BO-TUBE192 logical RGBWY cells in 80CH mode.

For IR-4:
- resolved source intensity -> IR-4 master intensity;
- source RGBWAUV color intent -> corresponding destination emitters;
- because the source uplight is effectively dimmerless while the destination IR-4 10CH profile has a physical master, a color-owned source interval with no separate source intensity ownership opens the destination master explicitly rather than remaining physically dark;
- strobe stays safely off unless a future explicitly reviewed source migration maps it.

For tube cells (no semantic master in the current V1 virtual-cell profile):
- source intensity is realized by scaling the decoded RGBWA emitter values;
- source UV is unsupported by the BO-TUBE192 virtual RGBWY cell and is reported as degraded rather than remapped to another emitter;
- intensity-only source behavior with no resolvable owned color cannot be represented as a virtual dimmer over released lower-layer color in current V1 and must report degradation rather than inventing a color.
